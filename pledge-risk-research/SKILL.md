# A股股票质押风控深度研究

## 核心原则

- 仅研究用户指定的 A 股上市主体，注明研究截至日、财务报告期和行情截止交易日。
- 服务于股票质押式回购风险决策，不给出二级市场买卖建议或无依据目标价。
- 将内容明确分为：**已核验事实、计算结果、分析推论、待核验事项**。
- 无法验证时原文写“暂未查证到可靠资料”，不得用行业常识、搜索摘要或历史本地报告补数。
- 不在报告或公开成果中写入本机用户名、绝对目录、Vault真实路径、邮箱、访问令牌、Cookie或其他个人环境信息；交付路径只在执行日志中按需显示。
- 同时分析四层风险，禁止以低资产负债率或低公司总质押率直接得出低风险结论：
  1. 上市公司主体经营与信用；
  2. 出质人回购能力；
  3. 股票抵押品价格、流动性和集中度；
  4. 股份权利限制、质押顺位与处置可执行性。

## 启动时必须读取

- 需要金融结构化数据时，先检查当前环境是否提供已获授权的金融数据技能或API，并完整读取其使用说明；若已安装 `westock-data`，必须遵守其路由规则，其能力域内不得以网页搜索或其他金融技能替代。
- 用户要求完整深度报告时，读取 [references/report-outline.md](references/report-outline.md)。
- 进行计算、同业比较、质押比例或来源质检时，读取 [references/data-qa.md](references/data-qa.md)。

## 标准工作流

### 1. 固定范围与口径

1. 确认公司全称、A 股代码、上市地点、实际控制人和总股本。
2. 报告时点使用当前日期；行情使用最近已收盘交易日，不把延时行情称为实时行情。
3. 财务数据至少覆盖近三年一期；若已披露更新的半年报或三季报，在满足用户指定期间后另加“最新补充”。
4. 年报使用审计合并报表，季度/半年度注明“未经审计”；归母与扣非、合并与母公司口径不得混用。
5. 报告标题之后、正文之前必须放置“撰写声明”，分别写明实际使用的软件和实际 AI 模型名称/版本；不得只写“AI”，也不得猜测或把技能中的示例名称当作实际运行环境。使用以下格式：

   ```markdown
   > **撰写声明**：本报告由 **{软件名称及运行形态}** 使用 **{实际 AI 模型名称/版本}** 撰写。
   >
   > - 撰写软件：{例如 Codex Desktop、OpenCode、WorkBuddy，以实际环境为准}
   > - AI 模型：{以当前运行环境可确认的模型标识为准}
   > - 用途：股票质押式回购风险研究，不构成二级市场投资建议
   > - 研究截至日：YYYY-MM-DD
   > - 数据限制：{行情截止交易日、财务报告期和关键未披露项}
   ```

   若运行环境未提供可核验的具体模型标识，AI 模型栏必须如实写“当前运行环境未提供可核验的具体模型标识”，不得自行补写模型名称。

### 2. 建立证据链

按以下优先级取证：

1. 公司公告、定期报告、审计报告、招股书；
2. 交易所问询/监管函及回复、证监会和其他监管处罚；
3. 公司官网、政府部门、行业协会；
4. 权威金融数据库；
5. 主流券商研报；
6. 财经媒体；
7. 股吧、雪球及自媒体，仅作舆情线索。

执行要求：

- 关键数据优先回到公告正文或 PDF，搜索摘要只能用于定位。
- 记录标题、发布主体、发布日期、数据报告期、URL、单位和是否审计。
- 对监管事件区分：行政处罚、行政监管措施、交易所纪律处分、监管函/问询函、立案调查；不得混称“处罚”。
- 对相互冲突的数据写明不同口径及选择理由；不能消除冲突时列为待核验。
- 本地文件只可作格式参考或中间缓存，不得作为金融事实来源。

### 3. 结构化取数与计算

- 使用当前环境已获授权的结构化金融数据源查询身份、财务、公告、股东、质押、行情、技术指标和一致预期；若使用 WeStock，遵守已安装版本的路由说明。没有可用结构化数据源时，优先查询交易所、监管机构和上市公司官方披露，并把无法取得的标准化字段列为待核验，不得用低质量聚合页面补数。同业财务尽量一次批量查询，统一日期和字段。
- 财务底稿至少含：收入、归母/扣非净利润、营业成本、毛利率、净利率、期间费用、经营现金流、应收票据与账款、合同资产、存货、货币资金、交易性金融资产、其他非流动资产、固定资产、在建工程、商誉、总资产、负债、有息债务、流动/速动比率。
- 从审计附注补充：客户/供应商集中度、应收账龄和坏账、存货库龄与跌价、受限资金、理财/存单底层、资本开支、担保、关联交易、诉讼、关键审计事项。
- 计算公式、分母和单位按 [references/data-qa.md](references/data-qa.md) 执行并复核。

### 4. 公司、行业与同业分析

- 公司分析覆盖业务、商业模式、核心产品、客户类型、收入/毛利结构、研发和护城河。
- 行业规模不强行合并多业务板块；按储能、充电、电能质量、数据中心电源、电池设备等相关子行业分别描述。
- 市场份额、客户名称和行业排名若只出现在投资者问题或媒体中，不能视为公司确认。
- 可比公司从业务相似度、收入结构、产业链位置和规模选择；先标注高/中/低可比度，再比较。
- 少量非严格可比样本不得用于强统计结论。若使用“±2 个标准差”，必须说明样本数量、同质性、计算口径和局限。

### 5. 财务真实性与偿债能力

- 对收入与利润变化按销量、价格、原料、产品结构、汇率、减值、投资收益和费用拆分；资料不足时写为推论或待核验。
- 将应收、存货、合同资产增速与收入比较，并核查账龄、期后回款、验收和退换货。
- 穿透现金及理财：受限资金、三个月以上存款、长期定期存单、结构性存款、质押、司法冻结；账面资金不等于即时可用现金。
- 存贷双高分析必须比较有息债务、借款利率、利息费用、存款/理财收益和资金受限状态。
- 将经营现金流与净利润累计、年度、季度分别比较，区分季节性、票据结算和应付款增长。
- 对资本开支核查预算、资金来源、转固、产能利用、折旧和需求不及预期情景。

### 6. 合规、造假预警与舆情

- 检索证监会、交易所、环保、税务、诉讼、担保、关联交易、审计机构和财务负责人变化。
- 对 [references/report-outline.md](references/report-outline.md) 中的十项预警逐项标为“已触发 / 部分触发 / 未触发 / 待核验”；“部分触发”需明确满足与不满足的条件，“待核验”不得写成“未发现”。
- 触发只表示需要穿透核验，不等于认定造假。
- 舆情按“公司互动/调研、主流媒体、匿名社区”分层，列出讨论主题、可核验事实和未确认主张；说明样本偏差、匿名性和帖子可删除性。

### 7. 股票与质押专项

- 计算近一年涨跌幅、最高/最低、最大回撤、成交额、换手率和波动率；技术指标注明具体日期和复权口径。
- 支撑/阻力只作历史形态参考，不得代替合同预警线或平仓线。
- 区分公司总质押率与单一出质人持股质押比例，检查数据时点和分母；不同来源不一致时以中登/公司最新公告优先。
- 核验出质人、质权人、股数、起止日、用途、解除/延期/补充质押、限售冻结、质押顺位和减持约束。
- 未取得融资余额、质押率、回购期限、预警线、平仓线、股份属性和内部制度时，不给出具体质押率或预警阈值。
- 至少用 -20%、-35%、-50% 股价冲击讨论补仓和处置能力；若缺少交易参数，仅列尽调所需输入，不虚构结果。

### 8. 形成结论与尽调清单

- 先给“主体信用、出质人、抵押品、法律处置”四层结论，再给条件性准入意见。
- 使用“事实 → 风险传导 → 触发指标 → 建议动作”，避免无条件使用“优质”“稳健”。
- 风险按重要性排序，至少覆盖股价、回购能力、应收现金流、盈利结构、行业竞争、流动性、担保、资本开支、治理和海外风险。
- 尽调问题必须要求可验证材料，覆盖战略、产品技术、客户订单、供应链、产能资本开支、财务真实性、合规治理和出质人专项。

### 9. Markdown 与 Obsidian 交付

1. 将用户可见成品保存到当前工具的交付目录：Codex 优先使用当前任务 `outputs/`；OpenCode、WorkBuddy 使用当前项目的 `deliverables/`、`outputs/` 或用户指定目录。文件名含公司、代码和截至日期，不直接写入应用配置目录。
2. 用户要求存入 Obsidian 时，按当前操作系统定位 Obsidian 配置，不得硬编码用户名、个人目录或历史 Vault：macOS 使用当前用户主目录下的 `Library/Application Support/obsidian/obsidian.json`，Windows 使用当前用户的 `%APPDATA%\\obsidian\\obsidian.json`，Linux 使用当前用户的 XDG 配置目录（通常为 `.config/obsidian/obsidian.json`）。若配置不存在或有多个候选 Vault，读取配置后选择当前打开的 Vault；仍无法唯一确定时再询问用户。
3. 报告必须保存到当前 Vault 的 Inbox 内：优先使用 Vault 中已经存在且名称明确为 `00-Inbox`、`Inbox` 或 `inbox` 的目录；用户指定了具体 Inbox 路径时以用户指定为准；均不存在时在当前 Vault 根目录新建 `00-Inbox`。不得把 Vault 根目录或其他历史目录当作 Inbox。
4. 在 Inbox 中新建本次报告的独立目录，只复制本报告，不修改其他笔记。推荐路径为 `<Vault>/<Inbox>/股票质押风控报告/<公司>_<代码>_<截至日期>/<文件名>.md`。
5. 使用当前操作系统可用的标准复制工具复制，且不得覆盖其他笔记；随后用 SHA-256 同时校验工作区和 Vault 文件，必要时再核对行数与字节数。不要在报告正文中记录真实绝对路径。
6. 交付前从本 skill 目录解析校验脚本并运行：

```bash
python3 <pledge-risk-research-skill-dir>/scripts/validate_report.py <report.md> --copy <obsidian-report.md>
```

如果没有 Obsidian 副本，省略 `--copy`。修复所有错误后再报告完成。

## 失败边界

- 已选择的结构化金融数据工具因网络或权限失败时，按该工具规则重试或申请权限；不得用网页搜索、记忆或低质量聚合数据替代其能力域。若当前环境没有该工具，改用官方一手披露并明确数据缺口。
- PDF 无文本层时使用 PDF 技能/OCR，并保留页码；无法可靠提取时不引用具体数字。
- 官方检索未发现事项时，写明检索范围和日期，不得把“未检索到”表述为绝对不存在。
- 不能取得出质人个人/关联主体资料时，明确“上市公司主体风险可判断，出质人回购能力待核”。

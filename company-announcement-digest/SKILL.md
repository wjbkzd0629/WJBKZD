# A股公司近一年公告全文概要

## 核心原则

- 仅处理用户指定的单一 A 股上市公司；核对公司全称、证券代码和上市交易所。
- 只纳入正式 A 股公告。排除新闻、研报、互动问答、媒体转载、行情信息、纯港交所披露及标题以“H股公告”开头的记录。
- 排除上市公司单独披露的内部工作制度全文，例如公司章程、担保管理制度、独立董事制度、董事会议事规则、审计委员会工作细则、募集资金管理制度、关联交易管理制度等；在下载正文前按标题完成识别，命中后直接跳过，不下载、不阅读、不生成摘要。
- 必须下载并阅读每份拟纳入公告的官方 PDF 或官方正文后再概括；搜索摘要只用于定位。已被标记为内部工作制度而跳过的记录不得下载或概括。
- 将计划、董事会审议、股东会批准、监管受理、实施完成等阶段分开表述，不把拟议事项写成既成事实。
- 无法提取正文时明确写“正文提取失败，暂无法可靠概括”，保留官方链接，不根据标题臆测。
- 不给投资建议，不预测收益；事实、计算、推论和待核验事项保持可区分。

## 时间口径

1. 使用 `Asia/Shanghai`。
2. 截止日以用户指定日期为准；未指定时使用执行当日。
3. “近一年”定义为截止日前连续 12 个完整日历月，首尾均含：开始日 = 截止日向前一年再加一天。例如截止日为 `2026-07-31`，区间为 `2025-08-01 00:00:00` 至 `2026-07-31 23:59:59`。
4. 按官方披露记录的发布时间筛选，不按文件落款日、下载时间或媒体转载时间判断。

## 数据源与工具路由

1. 优先使用当前环境已安装的权威金融结构化数据 Skill 或工具发现公告。
2. 若存在 `westock-data`，先完整读取并遵守其 `SKILL.md`；用公告列表能力分页取全量记录，用公告详情能力逐个公告 ID 获取详情，禁止合并多个详情 ID。
3. 无论使用何种结构化工具，最终均以巨潮资讯、上海证券交易所、深圳证券交易所等官方页面和官方 PDF 为证据原件。
4. 结构化金融工具不可用时，只能改用上述官方披露渠道继续核验；不得以普通搜索结果、媒体聚合页或本地旧报告替代金融事实。

## 标准工作流

### 1. 固定主体与区间

- 核对证券简称、公司全称、六位代码、交易所和 A 股身份。
- 简称可能对应多个主体时先澄清，不让数据源静默选错。
- 记录查询执行时间、截止日、区间起止和时区。

### 2. 分页抓取与筛选

- 抓取时间区间内所有分页；根据 `totalRecords` 和实际 `pageSize` 复算应抓页数，不盲信接口返回的页数。
- 保留原始公告 ID、标题、发布时间、官方页面/PDF URL 和来源渠道。
- 先按公司身份和发布时间筛选，再排除 H 股及非正式公告。
- 再按标题执行“内部工作制度”硬排除，见下方专节；命中后标记为 `excluded_internal_policy`，直接跳过，不进入精读。
- 优先按公告 ID 或 PDF 文件标识去重；缺少统一 ID 时，综合证券代码、规范化标题、发布时间和正文哈希判断。
- 同一公告在多个官方渠道重复时，只保留一个可直接打开的官方链接，并记录去重数量和理由。

### 2.1 内部工作制度硬排除

在去重和下载之前，仅根据官方标题判断该记录是否为上市公司内部工作制度全文。命中则立即跳过，不得下载 PDF、不得读取正文、不得 OCR、不得生成摘要。

判定为应跳过的，是记录本身即为制度、章程、规则、办法、细则、工作规程或议事规则的全文文件，而不是关于该文件的审议或修订事项公告。典型标题包括但不限于：

- 公司章程、公司章程修正案、章程修订对照表；
- 股东大会议事规则、董事会议事规则、监事会议事规则；
- 独立董事制度、独立董事工作制度；
- 董事会专门委员会工作细则或工作规程，包括审计、提名、薪酬与考核、战略等委员会；
- 总经理工作细则、董事会秘书工作制度；
- 担保管理制度、关联交易管理制度、募集资金管理制度、对外投资管理制度；
- 信息披露管理制度、投资者关系管理制度、内幕信息知情人登记管理制度；
- 董监高持股变动管理制度、防范控股股东及关联方资金占用管理制度；
- 内部控制、内部审计、财务管理、子公司管理、利润分配、委托理财、期货和衍生品交易等内部管理制度全文。

不要扩大排除范围：

- 标题为“关于制定/修订《……》的公告”“关于修改《公司章程》的公告”等事项公告，仍按通常规则纳入并精读；
- 董事会、监事会或股东会决议公告，即使议程包含修订章程或制度，仍纳入并精读；
- 同一披露同时包含审议公告和制度全文附件时，只保留并摘要审议公告，制度全文、章程全文、对照表附件按 `excluded_internal_policy` 跳过。

底稿中对每条跳过记录只保留 ID、标题、发布时间、官方链接、排除原因和 `excluded_internal_policy` 状态。

### 3. 逐份精读正文

- 只下载通过筛选且未被内部工作制度排除的公告。下载后记录 HTTP/下载状态、页数、可提取字符数和正文哈希。
- PDF 有文本层时提取全文；无文本层时使用当前环境的 PDF/OCR 能力，并抽查页码与金额。
- OCR 或提取仍失败时，不生成事实性摘要，只写失败说明。
- 每份摘要客观覆盖事项、关键金额/比例/期限、审议或实施阶段、重要条件与风险提示；简短公告约 80—150 个中文字符，定期报告或复杂交易可用 2—5 个要点。
- 金额、比例、日期和主体名称必须回到正文复核；不同公告口径冲突时并列呈现并解释选择。

### 4. 形成可审计底稿

保留一份结构化 JSON 底稿，至少包括：

- 公司全称、代码、交易所、检索区间、执行时间和数据源；
- 官方记录总数、抓取页数、区间内数量、H 股/非正式公告排除数量、内部工作制度排除数量、去重数量和最终纳入数量；
- 纳入公告记录其 ID、标题、发布时间、官方链接、页数、正文字符数、提取状态、摘要和错误；内部工作制度排除项只保留 ID、标题、发布时间、官方链接、排除原因和 `excluded_internal_policy` 状态，不填写下载、正文或摘要字段；
- 查询失败、下载失败、正文提取失败及校验异常。

### 5. 生成 Markdown

文件名使用：`公司简称（代码）近一年A股正式公告全文概要_开始日至截止日.md`。

正文依次包含：

1. 标题与统计区间；
2. 公司身份、权威来源和完整性结果；
3. 检索与审计结论；
4. 重要事项速览（只总结已核验内容）；
5. 按月份或发布时间排序的逐份公告全文概要；
6. 提取失败与待核验事项；
7. 数据来源、口径和限制。

每份公告至少列示公告时间、公告 ID（如有）、PDF 页数/正文字符数（如可得）、全文概要和可直接打开的官方链接。即使区间内没有公告，也要生成完整的零结果报告并完成交付。

Markdown 的检索与审计结论需列示内部工作制度排除数量，但不得把被排除的制度全文作为公告摘要条目，也不得根据其标题生成内容概述。

## Obsidian Inbox 强制交付规则

- 除非用户明确要求不写入 Obsidian 或指定其他目录，每次完成 Markdown 后都要同步到当前 Obsidian Vault 的 `00-Inbox/`。
- 先将成品保存在当前项目的 `outputs/`、`deliverables/` 或用户指定目录，再执行同步；不要把 Vault 当作唯一工作副本。
- 必须读取 `~/Library/Application Support/obsidian/obsidian.json`，选择 `open: true` 且时间戳最新的 Vault；不得硬编码历史 Vault 路径，也不得扫描整个主目录猜测位置。
- 优先运行本 Skill 的安全交付脚本：

```bash
python3 <skill-dir>/scripts/deliver_to_obsidian.py <report.md>
```

- 脚本只允许复制 Markdown 到 `00-Inbox`：同名且哈希一致时不重复；同名但内容不同时创建带“更新-YYYYMMDD-HHMMSS”后缀的新文件，不覆盖原笔记。
- 只新增本次成果及必要的 `00-Inbox` 目录，不修改、移动、删除或重命名任何其他 Obsidian 笔记，不触碰 `.obsidian/`。
- 以脚本返回的 `destination`、`sha256` 和 `status` 为交付依据；再次核对源文件与目标文件 SHA-256 一致。
- 遇到权限限制时申请所需写入授权并继续。没有活动 Vault、配置损坏或写入校验失败时，明确报告阻塞原因，不能把仅保存到工作区表述为“已加入 Obsidian”。

## 质量门槛

交付前逐项通过：

- 官方记录总数、分页抓取数、区间筛选数、H 股/非正式公告排除数、内部工作制度排除数、去重数和最终纳入数可以勾稽；
- Markdown 中公告条目数、标题数和官方链接数与最终纳入数一致；
- 所有公告属于目标公司和指定区间，不含 H 股公告、清单外主体或单独披露的内部工作制度全文；
- 所有 `excluded_internal_policy` 项均未下载、未读取、未 OCR、未生成摘要，只保留最小审计元数据；
- 每条事实性摘要都来自已读取正文；失败项有明确失败标记；
- 官方链接可追溯，关键金额、比例和日期已复核；
- 工作区 Markdown 与 Obsidian 副本哈希一致，或脚本明确返回 `already-present`。

## 失败边界

- 网络、权限或官方接口失败时，记录失败渠道、时间和错误；在安全范围内重试或申请授权。
- 无法证明抓取完整时，不得声称“全部公告”；改写为“已核验的公告”，并列出缺口。
- 不使用本地既有报告填补本次金融事实；本地成果只能作为格式参考。
- 不因公告数量多而静默截断。若受平台上下文限制，先完成结构化底稿与文件交付，再在对话中给出精简结论。
